## Gate questions

### 1. Does the full analysis run from a clean environment?

**Qualified yes.** The full pipeline completed from the pinned project environment with no failed step. The current audit used the already-created `.venv`, not a newly provisioned Conda environment. The package pins were satisfied, while the interpreter was Python 3.14.4 rather than 3.13. A fresh-environment rerun should therefore be performed before journal submission, although the present environment reproduces all analytical outputs.

### 2. Do all tests pass?

**Yes.** All 13 tests passed. They cover date parsing and continuity, event construction, percentile thresholds, partial-year handling, antecedent-feature leakage, chronological time splits, interval ordering, and output consistency.

### 3. Are all tables generated from code?

**Yes for analytical tables.** The numbered CSV and Markdown tables are generated by `scripts/run_all.py` and `src/heatwave_analysis/reporting.py`. No evidence was found of manual editing of numerical results. The requested original-article main/supplement table structure did not yet exist at the audit baseline.

### 4. Are all figures generated from code?

**Yes for the rebuilt figures.** Ten PNG/PDF pairs are generated by `src/heatwave_analysis/plotting.py`. The legacy files under `figures/` remain separate and are not evidence for the rebuilt analysis.

### 5. Are any values hard-coded?

**One material metadata value and several presentation annotations are hard-coded.** `scripts/run_all.py` overwrites the detected starting commit with the old SHA `926400ce49ebf2e8e87561beeedb7be93a19dcaf`; consequently, the audit-baseline `run_metadata.json` does not record the actual starting commit. Figure 1 also contains a hard-coded Dhaka city reference coordinate even though exact station provenance is unavailable. Numerical model estimates are computed, not hard-coded. Both material presentation/reproducibility issues require correction.

### 6. Do the report, tables, figures, and source code agree?

**Mostly, with diagnostic exceptions.** Primary numerical checkpoints agree across tables and generated reports. However, the selected count model is NB2 while `influence_diagnostics` derives leverage and Cook's distance from the Poisson fit and computes randomized quantile residuals using the Poisson distribution. The current Figure 6 therefore does not provide distribution-consistent NB2 diagnostics. The figure also flags an implausibly large number of years as influential. This must be corrected.

### 7. Do any manuscript-ready reports contain stale values?

**Yes.** The reports generated by the methods-first pipeline contain the hard-coded old starting SHA. The repository `README.md` also retains legacy claims and values, including urban-heat-island attribution, causal tree-cover wording, SARIMA primacy, and precise 2025–2029 counts. Those statements are not suitable for the original article. Core rebuilt estimates in `reports/statistical_analysis_report.md` match the current numerical tables.

### 8. Are there cases of target leakage?

**No leakage was identified in the prespecified primary association model.** Every rolling antecedent feature uses `shift(1)` before aggregation; training-only means and scales are used in held-out seasons; and same-day temperatures, heat index, apparent temperature, VPD, and event-derived quantities are prohibited. This is enforced by unit tests. The legacy notebook contains tautological or target-derived analyses, but it is not part of the rebuilt primary model.

### 9. Are incomplete years handled consistently?

**Yes in the rebuilt trend analysis.** Complete-calendar-year annual means end in 2023. March–June 2024 is retained because all 122 dates are present. The raw record is continuous from 1972-01-01 through 2024-11-18, with no duplicate or missing dates. The partial 2024 calendar year is not used as a complete annual mean.

### 10. Are all statistical claims supported by an output file?

**The rebuilt report claims are generally supported; the legacy README claims are not.** Temperature slopes, count-model estimates, association estimates, validation metrics, and sensitivity values have CSV sources. Unsupported legacy claims about urban amplification, human vulnerability, causal tree-cover effects, and exact future counts must not enter the new manuscript. A formal claim-to-evidence matrix is still required.

### 11. Are any confidence intervals or p-values inconsistent?

**No numerical inconsistency was found in the main trend, count, or association tables.** The primary count result reproduces as IRR 1.0288 per decade (95% CI 0.7275–1.4549; p = 0.8725). The March–June mean maximum-temperature trend reproduces as 0.1653 °C per decade (95% CI 0.0440–0.2866; p = 0.00757). The annual minimum-minus-maximum slope contrast is 0.0164 °C per decade (95% CI -0.0344–0.0671; p = 0.527), so separate significant slopes do not establish a significant difference. Count diagnostic intervals must be reconsidered after NB2-consistent diagnostic correction.

### 12. Are model-selection decisions reproducible?

**Yes, with incomplete NB2 diagnostics.** The scripted rule selects NB2 when empirical Poisson dispersion exceeds 1.2, NB2 improves AIC by more than 2, and convergence succeeds. The rerun reproduced Poisson dispersion 11.6375, Poisson AIC 659.8045, NB2 AIC 245.1811, and NB2 selection. The comparison table does not yet report NB2 Pearson/deviance-style diagnostics, and the residual/influence implementation is inconsistent with the selected distribution.

### 13. Are any models retained solely because they appeared in the old manuscript?

**No for the principal inference; partly yes for secondary forecasting output.** The primary NB2 count model and GEE association model were introduced by the methods-first rebuild. Forecasting remains because it was historically prominent, but validation shows climatology plus linear trend (mean rolling RMSE 1.114 °C) outperforms SARIMAX (1.607 °C). Future-count scenarios are not validated forecasts and should not be retained in the main article. Forecast validation may remain supplementary as a scientifically useful negative result.

## Warnings, convergence, and failures

The pipeline emitted three `RuntimeWarning: divide by zero encountered in scalar divide` warnings while computing VIFs. They arise from exact mathematical collinearity among screened meteorological summaries and reinforce the decision not to fit those variables jointly. The warnings should be documented or represented explicitly as infinite VIF values. No model reported a convergence failure, no tests failed, and no required baseline output was absent.

## First-gate decision

The methods-first branch is numerically reproducible and provides a credible analytical foundation, but it is not yet article-ready. The baseline passes the reproduction gate with required corrections: record the true starting SHA, remove the unproven map point, replace Poisson-derived diagnostics with NB2-consistent diagnostics, add missing trend and definition-sensitivity outputs, strengthen blocked validation, and segregate forecasting from the core inference.
